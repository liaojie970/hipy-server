> 面向日常配置人员：搞清后台「视频源管理」下三个页面的分工，以及**给 TVBox 等播放端配置源时到底该复制哪个 URL**。
>
> 菜单名已于 2026-10-21 重新梳理（统一不超过 4 个字，便于在折叠侧边栏里完整显示）。旧名 → 新名：

> 在线预览 → **效果预览**、在线编辑源 → **编辑源**。
>

## 一、一句话区分

| 页面 | 本质 | 存的是什么 | 典型操作 |
|---|---|---|---|
| **源规则** | 本机**已安装的单个源（规则文件）清单** | 磁盘上每个爬虫文件（`t4/spiders/xxx.py`、`t4/files/drpy_js/xxx.js`）及其元数据：分组、文件类型、`ext` 扩展参数、可搜索/可筛选/可快搜、排序、是否显示 | 上传源、在线编辑、刷新源（把磁盘文件扫进数据库）、启用/禁用、置顶/置底、删除 |
| **订阅配置** | **分发 / 授权视图**：决定"某台设备看到哪些源" | 订阅码 `code` + 正则 `reg` + 匹配模式 `mode`（0 正向匹配 / 1 反向排除）+ 状态 `status` + 到期时间 `due_time` | 新建订阅、启用/禁用、设过期时间、复制 **T3/T4 配置地址** |
| **上游仓库** | **上游目录**：别人 GitHub / Gitee 仓库里的规则清单 | 仅一份列表（源名 `rule` / 文件名 `name` / 体积 / 上游链接 `url` / 来源 `from`），保存在 `t4/files/json/drpy_rules.json` | 获取仓库数据（刷新列表）、勾选后「导入源」（下载 js 落到本机） |

同级还有两个页面：

- **参数配置**（原「配置中心」）：hipy 的键值参数与配置模板（`vod_config_*`），仓库地址、git 令牌/代理、解析等都在这里。
- **效果预览**（原「在线预览」）：用生成的配置渲染一套 CMS 页面，验证源能否正常出列表/详情/搜索。
- 「编辑源」为隐藏菜单，从源规则列表跳转进入。

后端落点（排查用）：

- 源规则：`app/apps/vod/views/views_rules.py`，接口前缀 `/api/v1/vods/rules`
- 订阅配置：`app/apps/vod/views/views_subs.py`，接口前缀 `/api/v1/vods/subs`
- 上游仓库：`app/apps/vod/views/views_houses.py`，接口前缀 `/api/v1/vods/houses`

## 二、数据流：三者是一条链，不是三套源

```
上游仓库（GitHub / Gitee 列表）
        │  「导入源」下载 xxx.js 落到 t4/files/drpy_js/
        ▼
源规则（本机已装源，active=1 的才会进配置）
        │  /config/{mode} 生成完整配置
        ▼
订阅配置（按 reg 对 sites 做一次过滤 + 到期/禁用校验）
        ▼
TVBox / 影视 App 的「配置地址」
```

对应关系需注意：

1. **上游仓库不产生源**：点「获取仓库数据」只是刷新 `drpy_rules.json` 这份目录清单；点「导入源」才会真正下载文件并登记到源规则。
2. **源规则才是源的唯一真身**：磁盘上有文件 ≠ 后台有记录，新放入的文件要点一次「刷新源」才会被扫描入库（例如精选内容生成的 `t4/spiders/亲子精选.py`）。
3. **源规则里「是否显示」关掉或 `is_exist=0` 的源，不会出现在任何配置里。**
4. **订阅不持有源**，只是对源规则结果的过滤和访问有效期控制，所以同一个源可以被多个订阅复用。

### 上游仓库地址怎么写（`vod_drpy_house1~3`）

值格式是 `仓库|目录`，仓库部分支持下面几种写法（`app/utils/httpapi.py` 的 `parseGitRepo`）：

| 写法 | 来源 | 列表里的「链接」 |
|---|---|---|
| `hjdhnx/dr_py` | github（默认） | `vod_git_proxy` + `raw.githubusercontent.com/...`，代理留空则直连 |
| `github:hjdhnx/dr_py` / `gh:hjdhnx/dr_py` | github | 同上 |
| `gitee:owner/repo` / `gt:owner/repo` | gitee | `https://gitee.com/owner/repo/raw/<分支>/...`（**不拼** github 加速前缀） |
| `https://gitee.com/owner/repo.git` | 按域名识别 | 同上 |
| `https://github.com/hjdhnx/dr_py` | 按域名识别 | 同 github |

要点：

- **gitee 仓库不需要加速前缀**，`vod_git_proxy` 只作用于 github 的下载地址。
- **默认三个仓库**（实测可用）：`hjdhnx/dr_py|js`、`qist/tvbox|js`、`gaotianliuyun/gao|js`。
- **`vod_git_proxy` 默认 `https://gh-proxy.com/`**：国内直连 `raw.githubusercontent.com` 基本不通（手机实测超时），必须靠加速前缀下载；`https://ghproxy.net/` 亦可（较慢）。调到打不开时换一个前缀即可，`api.github.com`（列表接口）本身通常可达。
- 历史坑备查：旧的默认前缀 `https://ghproxy.liuzhicong.com/` 已失效；gitee 镜像仓库常常被下架（HTTP 451 + `violation_name` 占位），所以默认值已回退到 github 仓库。
- 老环境升级后执行一次 `cd app && python db/migrate_git_house.py`（幂等，只改仍是旧默认值的项），再到「上游仓库」点一次「获取仓库数据」刷新链接。
- 「导入源」下载失败时会自动回退：先用列表里的 `url`（带加速前缀），再试 `raw_url`（原始地址），最后试去掉前缀后的直链，三者都不行才报错。

## 三、要配置"其他源"，该复制哪个 URL

### 结论

**复制「订阅配置」里那条订阅的 T3 / T4 配置地址**（行末「更多」→「T3配置」/「T4配置」）：

```
http://<服务器IP>:<端口>/config/0?sub=<订阅码>    # 0 = T4 模式，含 drpy js，最常用
http://<服务器IP>:<端口>/config/1?sub=<订阅码>    # 1 = T3 模式
```

这是播放端唯一认的「配置地址」，由 `app/apps/web/views.py` 的 `/config/{mode}` 实时生成：先用源规则里启用的源拼出完整配置，再按订阅的 `reg` 过滤 `sites`。

### 另外两个页面里的链接为什么不能填

| 位置 | 实际是什么 | 能否直接填 TVBox |
|---|---|---|
| 上游仓库列表的「链接」 | 上游 raw JS 文件地址：github 源为 `vod_git_proxy` 前缀 + `raw.githubusercontent.com/...`，gitee 源为 `gitee.com/<owner>/<repo>/raw/<branch>/...` 直链 | **不能**。只能用于「导入源」或手动下载 |
| 源规则「更多」→「直链」 | 本机 static 文件地址 `http://host/files/drpy_js/xxx.js` | **不能**当作配置地址。它是单个源文件，仅供调试查看、分享单文件或自建 json 配置时作为 `sites[].api` 引用 |

### 订阅正则到底过滤的是哪份数据（实现细节）

一句话：**过滤对象是最终生成的配置里的 `sites` 数组，按 `site['name']` 匹配**——不是上游仓库，也不是源文件名 / `ext` / URL。

`/config/{mode}` 的实际执行顺序（`app/apps/web/views.py`）：

```
源规则(status=1 & active=1 & is_exist=1) → 渲染配置模板 → 合并 vod_config_custom →
→ 按 sub.reg 过滤 sites(此时才发生) → 给 mode=0 的 type=4 源追加 ?sub=<订阅码> → 返回
```

由此推论，四条容易踩的规则：

1. **匹配的是「显示名」不是文件名**：`name` 可能是 `ext` 多行展开或 `ext@自定义名` 改名后的结果（如 `xxx2`、自定义名）。所以正则写 `亲子精选` 能命中，写 `亲子精选.js` 不命中。
2. **`vod_config_custom` 里手工追加的 `sites` 也会被过滤**（过滤发生在合并之后），自定义项需要带上 `order_num`，且名字要能被 `reg` 匹配到，否则会被订阅"吃掉"。
3. **`mode` 为空按 `0`（正向匹配）处理**；`reg` 为空时正向 = 结果为空、反向 = 全量，两个都别留空。
4. **T4 防盗参数是过滤之后才注入的**：只有过滤后留下的 `type=4` 源才会被追加 `?sub=<code>`，这是 T4 源必须带订阅码才能播的原因。

> 反过来验证：如果怀疑是"订阅把源过滤掉了"，把该订阅的 `mode` 临时改 `1`、`reg` 填一个不可能命中的串（如 `zzz_not_exist`），看 `sites` 是否变全量，即可区分是「源没进配置」还是「被 reg 排除」。

## 四、常见场景操作步骤

### 场景 1：从上游仓库新增源

1. **参数配置**里确认仓库地址可用（`vod_drpy_house1~3`，格式 `仓库|目录`，默认 `hjdhnx/dr_py|js`、`qist/tvbox|js`、`gaotianliuyun/gao|js`；github 写 `owner/repo`，gitee 写 `gitee:owner/repo`；`vod_git_proxy` 默认 `https://gh-proxy.com/`，必要时填 `vod_git_token`）。
2. **上游仓库** →「获取仓库数据」→ 搜索目标源 → 勾选 →「导入源」（提示"导入成功 N/N 个源"）。
3. **源规则** →「刷新源」→ 找到该源，确认「是否显示」为开、`ext` 等参数正确。
4. **订阅配置** → 修改目标订阅，让 `reg` 能匹配到它（或新建一条）→ 复制 T4 配置地址。
5. 播放端填入新地址 → 清缓存/重启 App 生效。

### 场景 2：只想给某台设备一个（或几个）源

在**订阅配置**新建订阅：

- `reg`：源名关键词，如 `亲子精选`（正则，支持 `|` 多选）
- `mode`：`0` 正向匹配（只保留命中项）
- `status`：启用；需要限时则填 `due_time`

然后复制该订阅的 T4 地址给该设备。参考已有示例：

| 订阅名称 | code | reg | mode | 含义 |
|---|---|---|---|---|
| 全部 | `dzyyds` | `.*` | 0 | 全量源 |
| 官源 | `luNhHy` | `官` | 0 | 只看名字含"官"的 |
| 18+ | `yellow1` | `密` | 0 | 只看命中的 |
| 不含18+ | `green1` | `密` | 1 | 排除命中的（反向） |

### 场景 3：反向排除（保留大部分）

`mode=1`，`reg` 填要**排除**的名字正则。注意 `reg` 为空时：正向匹配视为"无命中"（结果为空），反向排除视为"不排除"（等于全量），所以不要留空；`mode` 留空则按 `0`（正向匹配）处理。

## 五、报错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `参数【sub】不正确` | 库里已有启用中的订阅，`/config/0` 却没带 `sub`（或码太短） | 配置地址补上 `?sub=<订阅码>` |
| `不存在此订阅码:【xxx】` | `code` 拼错 / 记录已删除 | 复制订阅配置里的 T4 地址，别手抄 |
| `此订阅码:【xxx】已禁用` | `status=0` | 订阅配置里「设为启用」 |
| `此订阅码【xxx】已过期` | `due_time` 早于当前时间 | 修改到期时间或清空 |
| 配置能打开但**没有源 / 少了源** | 源未启用、`is_exist=0`、或订阅 `reg` 不匹配 | 源规则查「是否显示」；订阅配置核对 `reg`/`mode` |
| 上游仓库「获取仓库数据」失败 | GitHub API 限流或被墙 / Gitee 接口限流 | github 源：参数配置里清空/更换 `vod_git_token`；gitee 源：稍后重试（公开仓库无需令牌） |
| 上游仓库「链接」打不开 / 「导入源」全部失败 | `vod_git_proxy` 加速前缀已失效，或直连 `raw.githubusercontent.com` 被墙 | 换一个可用的加速前缀（默认 `https://gh-proxy.com/`，备选 `https://ghproxy.net/`），再点「获取仓库数据」刷新链接 |
| 上游仓库「获取仓库数据」报 `violation` / HTTP 451 | gitee 仓库已被下架或屏蔽（常见于镜像仓库） | 把该行换成 github 仓库（`owner/repo`），或删掉这个仓库 |

## 六、自检命令

确认某个订阅地址实际返回哪些源（在服务器上执行，把 IP/端口/码替换成自己的）：

```bash
curl -s "http://127.0.0.1:5707/config/0?sub=dzyyds" \
  | python -c "import sys,json;d=json.load(sys.stdin);print(len(d['sites']));print([s['name'] for s in d['sites']][:20])"
```

- 返回的 `sites` 数量应与"源规则里启用的源（经 `reg` 过滤后）"一致；
- 若 `sites` 为空，先看 `reg` 与 `mode`，再看源的启用状态，最后才怀疑配置模板。
