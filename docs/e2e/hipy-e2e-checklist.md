- 项目: hipy（后端 hipy-server / 前端 hipy-ui）

- 关联卡: dev / t_a1b8114f（E2E）、t_8d8df5c3（精选内容跨账号可见性）、t_08376e5e（getMenus 越权）
- 规模: **13 组 / 71 条** = 功能点层 12 组 63 条 + **闭环场景层 L 组 8 条**

> v0.2 的问题（自我评审）：只有"模块级功能点"，**没有业务闭环**。功能点各自能过，
> 不代表"站点配置→搜索→入库→审核→可见→运行时→播放"这条链走得通，也不代表权限/状态变更能正确回环。
> v0.3 因此改为**两层**：功能点层（每个模块本身可用）+ 闭环场景层（跨模块业务链闭合）。

## 2. 闭环场景层（L 组，8 条）——v0.3 新增

> 原则：**每条必须跨模块串联，且断言数据库/接口状态，而不是只看页面有没有报错。**

> **执行口径（用户 2026-10-10 确认）**
> 1. 运行时消费闭环（L2）**只验到"订阅生成 + 可见集合一致"**，不跑 t4 引擎
> 2. **写操作一律 dry-run 校验，做只读闭环**：不真实写入/删除/改可见，只验证
>    接口可达性、权限校验（403/放行）、入参校验、返回结构；跑完后库保持基线不变

| ID | 闭环 | 串联步骤 | 状态断言 |
| --- | --- | --- | --- |
| **L1** | 内容生产闭环（**dry-run**） | 站点配置 → `search` 拉候选 → `media/batch` 入库(不落库，校验入参与权限) → 设分类 → 审核 → 置可见 → `catalog` → `play` | 权限校验正确(放行/403)、入参校验正确、返回结构正确；`catalog`/`play` 对**已有**数据正常；库保持基线 354 |
| **L2** | 运行时消费闭环 | `kid_config` → 取可见集合 | 订阅生成成功(记录存在且启用)；可见集合 == `getVisibleList`(status=1 且 visible=1)；**不跑 t4 引擎** |
| **L3** | 内容状态闭环（**只读**） | 用**已有**数据验证状态语义：status/visible 与 `getVisibleList`/`catalog` 的一致性 | 已存在 status=1 且 visible=1 的条目全部出现在可见集合；不真实改状态 |
| **L4** | 权限闭环（**dry-run**） | 核对角色→菜单→权限标签映射；撤销授权走 dry-run 校验权限判定 | 映射与 DB 一致；撤销后判定为无权（不真实改授权） |
| **L5** | 越权闭环（后端为准） | 普通账号拿 admin 专属接口**直调**（绕过前端） | 后端 403（前端隐藏不算数）；只读接口按权限放行/拒绝 |
| **L6** | 账号生命周期闭环（**只读**） | 登录/登出/改密接口校验；注册与忘记密码只验入参与验证码校验路径 | 登录成功/失败、登出失效符合预期；不发真实邮件、不落新用户 |
| **L7** | 去重/幂等闭环（**dry-run**） | 对**已有**媒体重复提交入库请求 | 服务端去重判定正确（返回已存在/跳过），不产生新行 |
| **L8** | 基线不变校验 | 跑完复核 `curated_media` 行数等关键计数 | 全程只读，收尾计数与基线 354 完全一致 |

### 不可测 / 需降级的项（如实标注，不假装覆盖）

- **真实客户端播放**（TVBox 设备）：不在范围内，以 `play` 直链可用性 + t4 引擎本地跑替代
- **外部站点搜索**（bilibili 等）：依赖外网与对方可用性，易 flaky → 允许标注"跳过/环境受限"，**不计入通过率分母**
- **邮件闭环**（注册验证/忘记密码邮件）：不发真实邮件，只验生成与页面
